# 领域专属对话工作区

> 把一个大杂烩的 AI 对话,拆成按领域隔离的多个窗口。通用方法,与具体领域无关。

## 解决什么问题

默认情况下,所有对话都在同一个目录启动,于是共用一份历史、一套上下文。结果是:

| 症状 | 根因 |
|---|---|
| 问 A 领域的事,它拿 B 领域的结论回答 | 上下文串台 |
| 每次都要重新交代背景 | 长期状态没有落地成文件 |
| 想给某个领域定专属规则,一加就全局生效 | 规则没有作用域 |

## 原理

Claude Code 用**启动时的工作目录**当项目 ID。换目录启动 = 换一份对话历史、换一套加载的规则。

所以「建一个领域窗口」= 建一个文件夹 + 放一个 `CLAUDE.md` + 一个快捷方式。没有别的机制。

## 目录约定

```
<domain>/
├── CLAUDE.md              进这个目录自动加载的领域规则
├── .claude/agents/        领域专属 subagent
├── knowledge/             精炼后的知识,进 git
├── state/                 长期状态:进展、判断、待办,进 git
├── material/              原始素材:转录稿、截图文案,不进 git
└── .gitignore
```

`knowledge` 和 `state` 的区别是这套结构的核心:

| | knowledge | state |
|---|---|---|
| 内容 | 可复用的结论、原则、话术 | 具体的人、事、进度 |
| 变更频率 | 低,沉淀后基本不动 | 高,每次对话都可能更新 |
| 能否公开 | 脱敏后可以 | **通常不行** |

混在一起,是知识库最常见的死法 —— 想分享时发现拆不开。

## state 是省掉重复交代背景的关键

`CLAUDE.md` 里写一句「每次对话开场先读 `state/`」,窗口就有了连续记忆。不写这句,建再多文件夹也还是每次从头讲。

## material 为什么单独隔离

原始素材有三个特点:体积大、噪音多、常含第三方隐私(别人的聊天内容)。

它只是**加工的输入**,不是成果。让它进仓库,等于把仓库变成垃圾场,而且一旦要开源就得逐条清洗。用 `.gitignore` 从第一天就隔开,比事后清理便宜得多。

## subagent 什么时候真的有用

只有一个场景值得用:**主窗口不该被原文塞满**。

扔进去 300 行聊天记录,让主窗口逐条读,后面的对话就全被这些原文挤占了。派 subagent 去啃,只把结论带回来,主窗口保持干净。

不要为了「显得专业」而拆 subagent。subagent 每次调用都是空白上下文,不记得你上次说什么 —— 它是干活的临时工,不是顾问。需要连续记忆的角色,用窗口 + `state/`,不要用 subagent。

## 开始

```powershell
.\new-workspace.ps1 -Domain reading -Path "$env:USERPROFILE\reading"
```

脚本会建好目录、写入 `CLAUDE.md` 模板、创建桌面快捷方式。之后按你的领域改 `CLAUDE.md` 即可。

快捷方式打不开见 `TROUBLESHOOTING.md`。
